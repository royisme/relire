# Architecture

How Relire is put together: where each responsibility lives and how data moves. Read this before changing more than one area, or when you need to know which module owns something. Area-specific rules live in `.claude/rules/` and load automatically when you touch those files.

## Shape of the system

There is no server. Relire is a static PWA built by Vite into `dist/`; the user's browser calls the AI provider directly with the user's own key, and everything the user creates is stored in that browser (IndexedDB, plus a few synchronous settings in localStorage).

```
UI (src/components)  ──calls──▶  src/services/api.ts  ──▶  src/services/ai (tasks → provider)
        │                               │
        │                               └──▶ src/storage/cache.ts   (saved AI answers)
        ├──▶ src/utils/speech  ──▶ src/storage/audio.ts              (saved TTS clips)
        ├──▶ App.tsx state  ──usePersist──▶ src/storage/db.ts        (articles, vocab, stats)
        ├──▶ usePracticeCard / useShadowingLog ──▶ src/storage/shadowing.ts (recordings)
        └──▶ exercise screens ──▶ src/storage/exercises.ts           (units, item states, attempts)
```

GitHub Pages serves two things from one site (`.github/workflows/pages.yml`): the static marketing page from `marketing/` at the root, and the app build at `/app/`.

## Navigation and routes

There is no router dependency. The address is the single source of truth for where the learner is: `utils/routes.ts` parses `location.hash` into a `Route` and builds it back; `hooks/useRoute.ts` exposes the current route (a `useSyncExternalStore` over `popstate`, `hashchange` and its own event) and `navigate`. User navigation pushes history (`Link`, `navigate`); resolving a default (`#/` → `#/read`, `#/study` → `#/study/words`, `#/settings` on a wide screen → its first section) uses `replaceState`, so Back never lands on an address the learner did not choose. A push scrolls to the top; Back and forward keep the browser's scroll.

| Address | Screen |
| --- | --- |
| `#/read` (also empty, `#/`) | Library |
| `#/read/:articleId` | Reader; a missing article shows the not-found view |
| `#/study/words`, `#/study/shadowing` (`#/study` = words) | My study |
| `#/practice`, `#/practice?article=:articleId` | Practice: the article's exercise units, make a set, read aloud. Without `article` the app rewrites the address to the article read or practised last |
| `#/practice/:unitId` | One exercise unit on one sheet; a missing unit shows the not-found view with a link back to Practice |
| `#/progress` | Progress |
| `#/settings` | The section list on phones; from `md` it resolves to `#/settings/text-ai` |
| `#/settings/text-ai`, `speech`, `prompts`, `data`, `about` | Settings sections |
| anything else | Not-found view with a link to the library |

Things that are not in the address, on purpose: the sentence the reader opens at when sent from the shadowing log (`readerFocus`, shown once, dropped when the route changes), and the article the shadowing log opens at. A key request (`keyRequest` in `App`) is set when `MissingApiKeyError` is caught, when the key banner's button is pressed or when a feature reports a missing key; it records the address to return to and navigates to `#/settings/text-ai`, where the key field takes focus. It is dropped when the learner leaves Settings.

**Shell layout.** `App` renders `Header`, then a row of `Sidebar` (from `md`) and the content column (banners, then `<main>`). The sidebar is `sticky` in the page flow, 56px as a rail and 240px expanded; `App` publishes its width as `--sidebar-w` so the reader's fixed dock centres on the content column. Expanded exists only from `lg` and is the learner's choice (`relire_sidebar`), except in the reader, where it starts as a rail on every visit (`useSidebar`). Below `md` there is no sidebar; the header's menu button opens the same `NavTree` in a `Drawer`.

**Settings saves.** `SettingsPage` keeps a draft of `AppSettings` and of the prompt overrides. Each section saves only its own slice (`settings/slices.ts`), reads the stored value back (the storage helpers swallow errors, so a refused write would otherwise look saved) and shows the result through `useSaveStatus` / `SaveBar`. Text AI can also check a key against the provider before saving it (`checkTextKey`, with the draft's provider and model). Data and backup acts immediately.

## AI layer (`src/services/ai/`)

Split so each part has one job:

- `types.ts`: the contracts. `TextProvider` (`generateJson`, `checkKey`, `supportsAudioInput`, `supportsImageInput(model)`) writes structured answers; a `JsonRequest` may carry `images` (`{ data: base64, mimeType }`), an `AbortSignal` and `singleAttempt` (one try on the chosen model, no retry, no model switch); `SpeechProvider` (`synthesize`) returns a WAV `Blob`; `ProviderInfo` lists a provider's models, the ones that accept images (`text.imageModels`) and its voices; a `Provider` offers text, speech or both.
- `providers/`: one folder per provider (`gemini/` today) plus `index.ts`, the registry. Text and speech can use different providers, each with its own key.
- `prompts/`: the wording the AI receives. Templates in `prompts/defaults/<task>.<lang>.txt`, registered in `registry.ts` with their variables; `engine.ts` renders `{{var}}`, `{{#if var}}…{{/if}}`, `{{#if var=value}}`; `store.ts` keeps the user's overrides; `index.ts` prepares variables and builds provider-neutral `JsonRequest`s. `promptFingerprint` hashes the template in use. The six exercise prompts (`extract`, `hint`, `explain`, `grade`, `adaptive`, `exercises`) are registered like the others, so they are editable in Settings and fingerprinted.
- `tasks.ts`: what the app asks (`analyzeWord`, `analyzeSentence`, `assessPronunciation`, `annotatePronunciation`, and the exercise tasks below), written against `TextProvider` only.
- Exercise tasks (`tasks.ts`): `extractMaterial` (pasted text or 1-3 page images plus a mode to a draft), `hint`, `explainMistake`, `gradeOpenAnswer`, `generateAdaptiveDrills` and `generateExercises` (from an article). The Zod schemas in `types/exerciseAi.ts` and `services/exercises/importDraft.ts` are the contract: each request sends the matching JSON schema from `services/exercises/jsonSchema.ts` (`const` becomes a singleton `enum`), each answer is parsed with the Zod schema, and a failure throws `InvalidAnswerError` carrying the schema's own reasons (`ai/validate.ts`); no content is substituted. The templates describe exactly the fields their schema accepts, and `tests/prompts.test.ts` checks that against the schema shapes. Generated units carry an optional `articleQuote` per item (the article words the answer rests on); `generateExercises` leaves out each item whose quote does not occur in the article (`services/exercises/answerability.ts`, case, spacing and apostrophes ignored, `…` joins stretches), because that item could not be answered from the article, and a unit left with no items; the rest is kept, plain item numbers close up, and the call returns `{ units, dropped }`. Only when nothing is left does it throw (`InvalidAnswerError`, naming the quotes). A missing quote is not an error, only an unverified item. Dictation items (`NUMBER_DICTATION`) must carry `audioText` in drills and generated units.
- Image input: `extractMaterial` refuses with `ImageInputUnsupportedError` before any request when `supportsImageInput(model)` is false (Gemini: every `gemini-*` text model reads images, the TTS model does not; `info.text.imageModels` lists them). Extraction sends `singleAttempt` so the model the learner was shown is the only one used, and its `signal` cancels the request (`AbortError`, `isAbortError`); there is no automatic retry and no provider fallback. At most 3 images and 40,000 characters of text per request.
- `prosodySchema.ts`: provider-neutral JSON schema for markers; the provider forwards it when supported. The model writes spelling, not indices: per word a list of `{spelling, ipa}` syllables with silent letters in parentheses, a `groupEnd` flag, and connections naming the left word and its realized consonant spelling. `utils/prosodyResponse.ts` derives boundaries, silent ranges, group-final stress and connection ranges, applies the curated `utils/functionWords.ts` table to exact frequent words, then `utils/pronunciationMarkers.ts` validates the index-based record (also used for cache hits). Token alignment errors reject the sentence; a word-local inconsistency (bad spelling split, silent syllable, a vowel sound with no pronounced vowel letter) leaves only that word unresolved, and an invalid connection or stress mark is dropped alone. Structural validity does not certify phonetic correctness.
- `errors.ts`: `MissingApiKeyError` (App turns it into a key request: Settings → Text AI) and `errorMessage`.

## Data and persistence

| Data | Where | Lifetime |
| --- | --- | --- |
| Articles, vocabulary (with full explanation in `VocabWord.analysis`), stats | IndexedDB `articles`, `vocab`, `meta` | Until the user deletes them; backed up |
| Word analyses | IndexedDB `cache` | Until cleared |
| Sentence analyses, pronunciation markers, exercise hints and explanations, exercises generated from an article | IndexedDB `cache` | 30 days (markers: at most 1,000 entries; hints and explanations 2,000; generated exercises 200) |
| Shadowing recordings | IndexedDB `shadowing` (one record per article + normalized sentence, last 3 takes as Blobs) | Until deleted; deleted with their article; optionally backed up. Their reference clips are protected from audio trimming |
| Exercise units | IndexedDB `units` (key `id`, index `materialId`): one record per unit with its items, bound to an article or workbook | Until deleted; deleted with their material; always backed up |
| Item states | IndexedDB `itemStates` (key `unitId:itemId`, index `unitId`): current answer, checked result, hint/explanation flags | Until the unit is reset or deleted (or its material); always backed up |
| Attempts | IndexedDB `attempts` (key `id`, indexes `unitId`, `materialId`, `grammarTag`, `timestamp`): one row per check, with its own prompt and answer text | Kept through resets, unit deletes and **material deletes** (they carry their own text, so accuracy and the mistake notebook stay true); only a restore replaces them; always backed up |
| Reset tokens | IndexedDB `meta`, key `exerciseReset:<unitId>`: a counter per unit | Bumped, never removed; not backed up |
| Synthesized speech | IndexedDB `audio` (WAV Blobs) | Vocabulary clips (word, context sentence, examples) kept for good; the rest trimmed least-recently-used past 200 MB |
| Reader marker display/layer preferences | localStorage `relire_pronunciation_preferences_v1` | Per article, across browser sessions; no annotations or independent readiness flag; not backed up |
| Skipped marker sentences | localStorage `relire_pronunciation_skipped_v1` | Per article: sentence text → validation error, bound to the language/prompt identity; cleared when every skipped sentence later succeeds; not backed up |
| Settings and API keys, prompt overrides, UI language, theme, sidebar choice | localStorage `relire_app_settings_v1`, `relire_prompts_v1`, `relire_lang`, `relire_theme`, `relire_sidebar`, `relire_practice_card_pos` | Needed synchronously at startup |

Cache keys are language + prompt fingerprint + normalized text, deliberately not provider, model or article context, so switching models never re-spends tokens. Exercise AI is decided per task:

| Task | Cached | Key | Why |
| --- | --- | --- | --- |
| Hint (`api.fetchHint`) | `hint`, 30 days, 2,000 entries | language + fingerprint + exercise type, prompt, learner input, grammar tag, lesson context (normalized, context hashed) | The same item and input has the same hint; hits are revalidated with `HintSchema` |
| Explanation (`api.fetchExplanation`) | `explanation`, 30 days, 2,000 entries | as hint, plus the expected answer | Same reason; revalidated with `ExplanationSchema` |
| Exercises from an article (`api.generateExercises`) | `exercises`, 30 days, 200 entries | language + fingerprint + level + count + the article text sent (first 8,000 characters) | The kept set only (`{ units, dropped }`, revalidated on every hit), so a cached answer never brings back an item that was left out. The practice page always asks for a new set (`fresh`), since the button means "make another"; the cache protects other callers |
| Open-answer grading (`api.gradeOpenAnswer`) | never | | Every answer is different and the verdict must reflect this one |
| Adaptive drills (`api.generateAdaptiveDrills`) | never | | They follow the learner's latest mistakes |
| Extraction (`api.extractMaterial`) | never | | Depends on the learner's files and mode; one attempt, cancellable |

The new `hint`, `explanation` and `exercises` kinds use the existing cache store and its `kind` index without a DB version change. Marker keys additionally carry schema/tokenizer versions; hits are revalidated against current canonical source occurrences, so case/whitespace normalization cannot silently shift grapheme spans. The new `prosody` kind uses the existing cache store/index without a DB version change. Pronunciation assessments are never cached. The cache is never backed up; vocabulary audio optionally is.

## Key flows

- **Look up a word or sentence:** reader → `App` sets the active word/sentence → `api.fetchWordAnalysis` / `fetchSentenceAnalysis` → cache hit or `tasks` → provider → cache → sheet renders.
- **Pronunciation markers:** article entry → cache-only validation and readiness recovery (no provider request); complete usable answers restore the saved per-article display choice and layer flags. Missing/expired/invalid answers retain plain reading and the direct toolbar switch opens generation settings. Only explicit Generate → `usePronunciationMarkers` → frozen `api.createPronunciationSession` (language/settings/template) → validate cache first → sequential `annotatePronunciation` tasks across the whole article → stage successes. A sentence whose answer fails validation gets one fresh request, then is skipped (stays plain, recorded per article) and the queue continues; provider/key/network errors still pause it. Marker view unlocks once every supported sentence is staged or skipped; Generate retries skipped sentences; the direct toolbar switch applies the prepared snapshot; Stop/input changes/unmount invalidate scheduling and state writes, but an already sent request may finish and cache its original result. Identity includes exact article content, ID, language, prompt fingerprint and schema/tokenizer versions; prompt/language changes reset the session. Sentences over 2,000 characters are reported, never truncated. Missing `Intl.Segmenter` retains plain reading. Rendering uses original source text and local grapheme references, not model echoes, and never adds audio synchronization.
- **Listen to an article:** the reader's Listen button → `startSequence` with the article's sentences (`splitArticle`) → each sentence plays through `speakFrench`, whose `onSettled` starts the next; the current clip is loaded first, then the next two are prefetched. Pausing or stopping synthesizes nothing more. `ArticlePlayer` (a fixed overlay) shows play/pause, previous/next and stop; Escape, another speak button or leaving the article ends it.
- **Hear text:** `SpeakButton` → `toggleSpeech` → `clips.loadSpeech` (stored clip, else provider, then store) → `playback` publishes loading/playing through `state.ts`; every button with the same text reflects it.
- **Save a word:** `App` stores the word with its analysis, then prefetches word and sentence audio so it is protected and offline.
- **Shadowing:** `ShadowingRecorder` → `useShadowingRecorder` (record, stop, play back) → `api.assessPronunciation` → `onAssessed` adds the score to stats.
- **Shadow a sentence:** the sentence pill's microphone → `usePracticeCard.open` claims the capture lock, pauses an article sequence (`suspendSequence`) or stops speech, then records a `Take` with a level meter → Stop → `addTake` (one transaction: article still exists, append, drop the oldest past 3) → the card shows the latest take. Any other playback (`setBeforePlay`) or the reader's word/sentence sheet interrupts a take without saving. Closing the card, switching article or leaving the reader discards a running take.
- **Shadowing log:** My study → Shadowing → `useShadowingLog` (lists and subscribes to the store) → rows by article in `splitArticle` order; "open in reader" sets the reader's `focusText`.
- **Backup:** `DataSection` → `exportData` / `importData` in `db.ts` (never API keys; includes prompt edits; audio and shadowing recordings optional). Recordings are validated in full by `parseShadowingBackup` before one transaction replaces the stores; no `shadowing` key keeps the current recordings, `[]` clears them, malformed input rejects the whole restore. `units`, `itemStates` and `attempts` are always exported (no toggle). `importData` validates them with the Zod schemas in `exerciseBackup.ts` before the transaction opens (bad shape, duplicate ids, a state pointing at an unknown unit or item, a unit whose material the backup lacks all reject the whole restore); a key that is absent keeps the stored rows, `[]` clears them. Rows the restore did not replace but whose owner vanished (units of an article the backup dropped, with their states) are removed in the same transaction; attempts are only replaced when the key is present. A restore bumps the reset token of every unit that existed before it.
- **Check an answer:** the exercise screen grades (deterministically, or an AI grade for open answers) and calls `exercises.checkItem({ unitId, itemId, resetToken, answer, result })`, where `resetToken` was read with `getResetToken(unitId)` when the work behind the result started. One transaction over `units`, `itemStates`, `attempts` and `meta` checks the unit and item exist and the token still matches, then writes the item state and one attempt (material, grammar tag, prompt, reference answer and answer text come from the stored unit). Any failure aborts the whole transaction and rejects (`StaleResetError`, `UnitGoneError`, `ItemGoneError`, or the storage error); the screen shows it and offers retry, never a fake success. An item that is already checked returns `{ created: false, state }` with the committed state and writes nothing, so a double click or a second tab cannot duplicate an attempt. Drafts and hint/explanation flags go through `saveItemProgress` (state only, no attempt; a checked item keeps its answer). Listeners of `subscribeExercises` run after commit and re-read.
- **Reset a unit:** `exercises.resetUnit(unitId)` deletes the unit's item states, increments its reset token and returns the new one, in one transaction; attempts stay. Work that started before (an AI grade, a hint, a delayed draft) still holds the old token, so its write rejects with `StaleResetError` and the screen drops it silently. The screen keeps using the returned token from then on. Deleting a unit, deleting its material (`deleteArticleData`: article, recordings, units and item states in one transaction) and restoring a backup bump the token too.
- **Generate exercises:** Practice → `GenerateForm` (level, count) → `useExerciseGeneration.make` → `api.generateExercises(…, fresh)` → `tasks.generateExercises` (schema, then `keepAnswerable`) → `{ units, dropped }` → `toStoredUnits` (fresh ids, `unitNumber` continuing after the article's highest, `answerSource: 'ai'`, no `articleQuote`) → `exercises.saveUnits(articleId, …)` (one transaction; the article must still exist) → `subscribeExercises` refreshes the list. The button shows the work by swapping its icon; the one status line below it says what was made, how many items "could not be checked against the article and were left out", or the real error (a model answer the schema rejects is wrapped in a translated sentence, `utils/aiErrorText`). `MissingApiKeyError` goes to the key request (Settings → Text AI). Leaving the page does not cancel the request (the answer was paid for); it is still saved, and touches no screen state.
- **Answer and check:** `UnitView` → `useExerciseUnit(unitId)` reads the reset token, the unit and its item states, and keeps one `ItemRuntime` per item (answer, checked result, flags, what it is waiting for, the last error). Typing calls `setAnswer`: local state at once, and a draft write (`saveItemProgress`, state only, no attempt) after 350 ms of quiet, flushed on `pagehide` and when the unit is left. A failed draft write shows on the footer's status line. Check (`exerciseUnit/actions.runCheck`) grades with `gradeUnitItem`; a `needs-ai` answer goes to `api.gradeOpenAnswer` (words only, never a score) and its feedback is stored in `CheckedResult.aiFeedback`; then `exercises.checkItem` writes state and attempt in one transaction. Every write carries the token read when the work began. A result that arrives after the learner left the unit or reset it is dropped silently (`isCurrent`); a `StaleResetError` while the token is still ours means another tab moved it, and the unit is read again. Hint and Explain call `api.fetchHint` / `fetchExplanation`, show the answer (under the item, or in a `Sheet`), then save `hintShown` / `explanationShown`; only the flags are stored, so after a reload asking again is answered from the 30-day cache. Reset (`resetUnit`, after a confirmation that says the history is kept) returns the new token, clears the sheet and drops pending drafts. Enter and the character bar work through the text fields a control registers (`registerInput`), so a control never handles keys: `ItemRow` moves to the next blank, then the first empty one, then checks, and ignores Enter during IME composition; `CharacterBar` inserts at the cursor of the field the sheet bound on focus and never takes focus itself.
