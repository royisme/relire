# Architecture

How Relire is put together: where each responsibility lives and how data moves. Read this before changing more than one area, or when you need to know which module owns something. Area-specific rules live in `.claude/rules/` and load automatically when you touch those files.

## Shape of the system

There is no server. Relire is a static PWA built by Vite into `dist/`; the user's browser calls the AI provider directly with the user's own key, and everything the user creates is stored in that browser (IndexedDB, plus a few synchronous settings in localStorage). A future hosted, paid service would enter only through the AI access boundary (`src/services/ai/access.ts`): it is deliberately not built, and no account, plan, balance or remote usage exists.

```
UI (src/components)  ──calls──▶  src/services/api.ts  ──▶  src/services/ai (access → tasks → provider)
        │                               │
        │                               └──▶ src/storage/cache.ts   (saved AI answers)
        ├──▶ src/utils/speech  ──▶ src/storage/audio.ts              (saved TTS clips)
        ├──▶ App.tsx ──explicit writes──▶ src/storage/db.ts          (articles, before state updates)
        ├──▶ App.tsx state ──usePersist──▶ src/storage/db.ts         (vocab, stats)
        ├──▶ usePracticeCard / useShadowingLog ──▶ src/storage/shadowing.ts (recordings)
        └──▶ exercise screens ──▶ src/storage/exercises.ts           (units, item states, attempts)
```

GitHub Pages serves two things from one site (`.github/workflows/pages.yml`): the static marketing page from `marketing/` at the root, and the app build at `/app/`.

## Local PDF resources and verification

`scripts/pdfjsAssets.ts` emits PDF.js's worker, cmaps, standard fonts, wasm/fallback decoders and ICC profiles to `pdfjs/`, and serves the same files in development. Runtime URLs resolve against Vite's relative base and the document base, not a root URL or CDN. Workbox precaches the entire resource directory (including `.mjs`, `.bcmap`, `.pfb`, `.ttf`, `.wasm` and `.icc`); its 3 MiB per-file cap includes the installed worker (about 1.3 MB). This adds about 5 MB of offline PDF resources even before the import screen ships.

`bun scripts/check-import-material.ts` builds the app plus a **test-only** entry (`material-test.html`), serves it under `/app/` on port 5174 and uses installed Chrome, without providers or screenshots. It checks real local image/PDF rendering, worker/font paths, protected/oversized PDFs, cancellation and cleanup, and offline rendering plus availability of all precached PDF resources. It removes its temporary build and stops the server/browser. The production import pages make the PDF.js library reachable through the lazy PDF adapter. The material harness remains an independent service check; `scripts/check-import-workspace.ts` checks actual production exercise-import page loading and offline PDF selection under `/app/`.

## Data tables

Library's `LibraryArticlesTable`, Practice's `SetTable` and `UnitTable` compose `ui/table` directly with TanStack Table v9 column definitions and row models (`useTable`, `rowSortingFeature`, `createSortedRowModel`, `getSortedRowModel`). No DataTable wrapper owns page behavior. `SortableHeader` shares only the header button, arrow and `aria-sort`; pages own filtering, empty/no-match states and confirmations. Unit sheets link back to their set page; Reader passage links still return to the exact exercise sheet.

## Navigation and routes

There is no router dependency. The address is the single source of truth for where the learner is: `utils/routes.ts` parses `location.hash` into a `Route` and builds it back; `hooks/useRoute.ts` exposes the current route (a `useSyncExternalStore` over `popstate`, `hashchange` and its own event) and `navigate`. User navigation pushes history (`Link`, `navigate`); resolving a default (`#/` → `#/read`, `#/study` → `#/study/words`, `#/settings` on a wide screen → its first section) uses `replaceState`, so Back never lands on an address the learner did not choose. A push scrolls to the top; Back and forward keep the browser's scroll.

| Address | Screen |
| --- | --- |
| `#/read` (also empty, `#/`) | Library |
| `#/import/article` | In-memory article import (Read area); does not reserve any reader id |
| `#/import/exercises` | In-memory exercise import (Practice area) |
| `#/read/:articleId` | Article prose in Reader; a missing article shows the not-found view |
| `#/passage/:unitId` | The unit’s exact passage in the same Reader; unavailable sources show a recoverable not-found view |
| `#/study/words`, `#/study/shadowing`, `#/study/mistakes` (`#/study` = words) | My study |
| `#/study/grammar/conjugation`, optional `?verb=<infinitive>` (`#/study/grammar` = the same page) | My study → Grammar: the Conjugation page |
| `#/practice` | Practice: exercise-set data table (search, level filter, sorting, confirmed delete), Add exercises dialog, and read aloud |
| `#/practice/set/:setId` | One exercise set and its exercise table, with confirmed exercise/set deletion; missing sets show not-found with a link to Practice |
| `#/practice/:unitId` | One exercise unit on one sheet; a missing unit shows the not-found view with a link back to Practice |
| `#/progress` | Progress |
| `#/settings` | The section list on phones; from `md` it resolves to `#/settings/ai/text` |
| `#/settings/ai/text`, `ai/ocr`, `ai/speech` (bare `ai` opens text) | AI services: Text AI, OCR or Speech synthesis on the same page; `?key=1` focuses the key, `?return=` carries the address to go back to |
| `#/settings/practice`, `prompts`, `data` | The other Settings sections |
| `#/about` | Standalone About |
| anything else | Not-found view with a link to the library |

Both Reader routes accept an optional `?sentence=` focus (nonblank, at most 4,000 characters), so a shadowing-log return keeps its source and sentence across reload and native history. Focus is derived from the first normalized sentence match, never stored as a positional index. The log’s initial source filter remains in memory. A key request (`keyRequest` in `App`) is set when `MissingApiKeyError` is caught, when the key banner's button is pressed or when a feature reports a missing key; it records the address to return to and navigates to the AI services page on the purpose that needs it (`text` for lookups, generation and grading; `ocr` for images and PDFs; `speech` for speech), where the key field takes focus. It is dropped when the learner leaves Settings.

**Article entry.** App’s `openArticle` opens the Reader. The selected unit remains route-owned across reload. Passage links use `#/passage/:unitId`; they do not go through article entry or fall back to article prose.

**Shell layout.** `App` renders `Header`, then a row of `Sidebar` (from `md`) and the content column (banners, then `<main>`). The sidebar is `sticky` in the page flow, 56px as a rail and 240px expanded; `App` publishes its width as `--sidebar-w` so the reader's fixed dock centres on the content column. Expanded exists only from `lg` and is the learner's choice (`relire_sidebar`), except in the reader and on exercise sheets, where it starts as a rail on every visit (`useSidebar`). Below `md` there is no sidebar; the header's menu button opens the same `NavTree` in a `Drawer`. The independent 40px collapse/expand icon sits at the sidebar top, outside `NavTree`; no collapse control appears in the drawer. The footer ends with Install, Settings, About. Expanded desktop owns study and Settings subnavigation; rail/mobile draw study page links locally and Settings keeps its existing responsive section list. Route destinations are links with `aria-current="page"`; `Segmented` remains a filter radio group with roving focus, four arrow keys and Home/End.

**Settings saves.** `SettingsPage` keeps a draft of `AppSettings` and of the prompt overrides. Practice and the prompts each save their own slice (`settings/slices.ts`); the AI page saves one `ai` slice holding all three purpose selections, every key they use and the model and voice remembered per speech engine (`speechChoices`, validated like the current selection), so no purpose is saved without the others. A save reads the stored value back (the storage helpers swallow errors, so a refused write would otherwise look saved) and shows the result through `useSaveStatus` / `SaveBar`. The AI page also checks a key against its provider, or previews the speech voice, with the draft and without saving (`getAiAccess(draft).checkConnection`, `testSpeech`); discovery through `useModelCatalogue` is page-local and never stored. Data and backup acts immediately.

## Import pages

Two pages, one per area, each its own component so state and guard ownership never carry over between them: `ImportArticlePage` (Read, `#/import/article`) and `ImportExercisesPage` (Practice, `#/import/exercises`). They share the intake in `components/import/`: `SourceInput` (file chooser, drop, clipboard, PDF page selection and the consent panel: provider, model, what is sent), `LeaveDialog`, and the hooks `useImportSource` (lifetime and one cancellable run, stale results rejected; the page supplies what the run does) and `useImportSession` (leave guard, start over, drop and paste). The run pins an `AiAccess` snapshot (settings and keys, in memory) before asynchronous page rendering and passes it to the api function. Missing keys stay on the page. Files and image base64 never persist.

**Article import.** Up to five images or five selected PDF pages go to `api.transcribeMaterial` (a text-only task on the OCR selection that returns `{ title, text }`); pasted text goes straight to review with no AI request at all, so its consent panel says nothing is sent. A chosen file and pasted text exclude each other (the text field and the file chooser disable one another, and the source controls remove images or the PDF and clear text), so neither is silently ignored. Review edits the title, level (the article editor's list, default B1) and text; Save writes one article (`db.saveArticle`), releases the guard, tells App's library, then opens the Reader. A title and text are required, and the title is never invented.

**Exercise import.** The extraction flow: `api.extractMaterial` with a mode (complete, extract, generate), collapsed question review with answer provenance, explicit inclusion and blockers. Review edits or inclusion changes invalidate preparation; a failed storage call retains the prepared set, unit and item identities. Included-unit promotion errors block the entire save. Save needs a title and a level (required, blank by default; it is part of the preparation) and writes one new batch with at least one valid included unit, then opens the new exercise set page. It never creates an article.

The article import saves one article (`db.saveArticle`); the exercise import saves one batch of units (`exercises.saveUnits`, one transaction; every unit shares one `setId`, `level` and `createdAt`). Neither saves the other. Collisions always reject; an existing ID is not a retry receipt. It creates no states, attempts or schema metadata.

`index.html` synchronously owns history-position recording before deferred modules; it merges history.state and records native hashes while the application loads. `utils/importNavigation` consumes that recorder: route publication stays at the import page until the Dialog decision, queued browser events coalesce before restoring the real origin entry, Keep retains draft/history, and Discard replays the saved traversal or link intent. Canonical replacements retain position. Successful save releases protection before navigation. Dirty reload/close uses beforeunload; pending saves cannot discard. Navigation API current-entry indices supplement genuinely older untagged entries, but routine operation does not require it. Same-document entries fabricated before the earliest synchronous document script cannot be direction-recovered without that API; the normal recording contract begins at that script, not at application mount.

## Progress and adaptive drills

`components/progress/ExerciseProgress` preserves the existing dashboard statistics and IPA chart. `useExerciseAccuracy` re-reads `accuracyByGrammarTag()` on exercise events, ignores stale reads and reports real read errors inline; no source-presence filter is applied. `services/exercises/accuracy` sums correct/total counts by taxonomy area and selects up to three lowest-ratio nonperfect tags, breaking ties in taxonomy order. Only attempted areas appear.

`useAdaptiveDrills` asks `api.generateAdaptiveDrills` with those disclosed targets and recent wrong snapshots limited to the targets and the existing prompt cap. Controls start at B1/eight items. `services/exercises/fromDrills` validates the complete result, rejects off-target tags and passage-dependent reading cloze, and prepares fresh set/unit/item IDs: one mixed-type unit in a new set titled with the drill title, at the form's level, explicit item types and AI answer provenance, no import source or invented passage. No article is created. `saveUnits` commits it before the sheet opens. Failed writes retain the same payload/IDs for a save-only retry; collisions still reject. Prepared unsaved sets reuse `useImportGuard` and its Dialog/beforeunload protection, disable edits until explicitly discarded, and cannot discard while saving. Leaving during AI generation invalidates the session and drops late output before storage; there is no background set creation.

## AI layer (`src/services/ai/`)

Split so each part has one job:

- `types.ts`: the contracts. `TextProvider` (`generateJson`, `checkKey`, `supportsAudioInput`, `imageInputCapability(model)`) writes structured answers; a `JsonRequest` may carry `images` (`{ data: base64, mimeType }`), an `AbortSignal` and `singleAttempt` (one try on the chosen model, no retry, no model switch); `SpeechProvider` (`synthesize`, plus an optional `acceptsVoice`) returns a WAV or MP3 `Blob`; `ProviderInfo` lists a provider's models, the ones that accept images (`text.imageModels`, static defaults) and its voices (an empty list means the provider takes any voice ID, drawn as a free-text field), an optional `defaultBaseUrl` (the learner may override the endpoint) and `requiresKey` (false for a local provider that needs none); `speech.device` declares the platform's own voice, which has no key, model, voice list or clip and throws `DeviceVoiceError` from `synthesize`; a `Provider` offers text, speech or both and may carry a `ModelCatalogue`. `Capability` is `supported`, `unsupported` or `unknown`; only confirmed incompatibility blocks a request.
- `access.ts`: `getAiAccess(settings?)` is the one execution boundary every feature uses (`AiAccess`: `isConfigured`, `selection`, `text`, `synthesize`, `checkConnection`, `listModels`). `createByokAccess` snapshots the settings and keys in memory, resolves each purpose's provider and model, and binds them into a `TextExecution` (model, image capability, `generateJson`) so tasks receive no credentials. It is the deliberate replacement point for a future hosted, paid service: such a backend would own platform secrets, identity, quotas, idempotency and authoritative usage, and this browser code would call it instead. Nothing of that backend exists here, and there is no fallback between the two.
- `catalogue.ts`: `normalizeModelId` accepts a nonempty ID of at most 512 characters without control characters, strips a resource prefix (`models/`), and never requires the ID to be in a static list; `purposeCapability` maps a purpose to its capability. A stored custom model ID roundtrips through a reload.
- `providers/`: one folder per provider (`gemini/`, `openai/`, `anthropic/`, `ollama/`, `fish/`) plus `index.ts`, the registry. Gemini, the OpenAI-compatible provider (whose editable Base URL also serves DeepSeek, Qwen or a self-hosted gateway), Anthropic and Ollama write text and read images; Gemini TTS and Fish Audio (browser-direct, MP3) speak, and `device/` is the browser's own voice offered beside them. Ollama declares `requiresKey: false`, and its help text says the local server has to allow this origin in `OLLAMA_ORIGINS`; Anthropic sends `anthropic-dangerous-direct-browser-access`, which the API requires for a browser origin. An endpoint override is stored per provider, validated (`http(s)` only, no credentials, query or fragment) in `services/ai/baseUrl.ts`, and carried by the access snapshot; an unusable stored endpoint fails the request instead of silently posting to the default host. Text, OCR and speech each name their own provider and key, and one key per provider is shared by every purpose that names it; changing one purpose's provider never changes another's selection.
- `prompts/`: the wording the AI receives. Templates in `prompts/defaults/<task>.<lang>.txt`, registered in `registry.ts` with their variables; `engine.ts` renders `{{var}}`, `{{#if var}}…{{/if}}`, `{{#if var=value}}`; `store.ts` keeps the user's overrides; `index.ts` prepares variables and builds provider-neutral `JsonRequest`s. `promptFingerprint` hashes the template in use. The six exercise prompts (`extract`, `hint`, `explain`, `grade`, `adaptive`, `exercises`) are registered like the others, so they are editable in Settings and fingerprinted.
- `tasks.ts`: what the app asks (`analyzeWord`, `analyzeSentence`, `assessPronunciation`, `annotatePronunciation`, and the exercise tasks below), written against `TextProvider` only.
- Exercise tasks (`tasks.ts`): `extractMaterial` (pasted text or 1-5 page images plus a mode to an exercise draft), `transcribeMaterial` (1-5 page images to an article's `{ title, text }`, schema in `types/transcription.ts`), `hint`, `explainMistake`, `gradeOpenAnswer`, `generateAdaptiveDrills`, `generateExercises` (from an article) and `conjugateVerb` (one verb to `ConjugationAnswerSchema`). The Zod schemas in `types/exerciseAi.ts` and `services/exercises/importDraft.ts` are the contract: each request sends the matching JSON schema from `services/exercises/jsonSchema.ts` (`const` becomes a singleton `enum`), each answer is parsed with the Zod schema, and a failure throws `InvalidAnswerError` carrying the schema's own reasons (`ai/validate.ts`); no content is substituted. The templates describe exactly the fields their schema accepts, and `tests/prompts.test.ts` checks that against the schema shapes. Generated units carry an optional `articleQuote` per item (the article words the answer rests on); `generateExercises` leaves out each item whose quote does not occur in the article (`services/exercises/answerability.ts`, case, spacing and apostrophes ignored, `…` joins stretches), because that item could not be answered from the article, and a unit left with no items; the rest is kept, plain item numbers close up, and the call returns `{ units, dropped }`. Only when nothing is left does it throw (`InvalidAnswerError`, naming the quotes). A missing quote is not an error, only an unverified item. Dictation items (`NUMBER_DICTATION`) must carry `audioText` in drills and generated units. Generated units with any effective `READING_CLOZE` item (including an item type override) must carry `readingPassage`; this generation-only requirement also validates cache hits, without tightening stored units or backups.
- Image input: `extractMaterial` and `transcribeMaterial` refuse with `ImageInputUnsupportedError` before any request when the image capability is `unsupported` (ocr purpose). Gemini's small verified hint table marks its known text models as reading images and its TTS model as not; any other ID is `unknown`, which reaches the provider and fails with the provider's real error rather than a local refusal. Extraction sends `singleAttempt` so the model the learner was shown is the only one used, and its `signal` cancels the request (`AbortError`, `isAbortError`); there is no automatic retry and no provider fallback. At most 5 images and 40,000 characters of text per request.
- Model discovery: each provider's `catalogue` calls that provider's official listing endpoint (key in a header, never the URL) through `ModelCatalogue.listModels`: Gemini `GET /v1beta/models` following `nextPageToken`, the OpenAI-compatible and Anthropic `GET /models` following `has_more`/`last_id`, Ollama `GET /api/tags`, Fish Audio `GET /compat/v1/models`. Every list is bounded, deduplicated by canonical ID and abortable; malformed or empty responses throw and never substitute defaults. Fish's `transcribe-1` is the one confirmed non-speech model and is kept out of the voice candidates. Fetched entries carry provider metadata and, when a model's `supportedGenerationMethods` lacks `generateContent`, an `unsupported` capability; otherwise the static hint table decides or the answer is `unknown`. Fetched entries carry provider metadata and, when a model's `supportedGenerationMethods` lacks `generateContent`, an `unsupported` capability; otherwise the static hint table decides or the answer is `unknown`. `generateContent` alone proves neither image input nor audio output. No list is persisted, and a successful fetch is discovery, not a test.
- `prosodySchema.ts`: provider-neutral JSON schema for markers; the provider forwards it when supported. The model writes spelling, not indices: per word a list of `{spelling, ipa}` syllables with silent letters in parentheses, a `groupEnd` flag, and connections naming the left word and its realized consonant spelling. `utils/prosodyResponse.ts` derives boundaries, silent ranges, group-final stress and connection ranges, applies the curated `utils/functionWords.ts` table to exact frequent words, then `utils/pronunciationMarkers.ts` validates the index-based record (also used for cache hits). Token alignment errors reject the sentence; a word-local inconsistency (bad spelling split, silent syllable, a vowel sound with no pronounced vowel letter) leaves only that word unresolved, and an invalid connection or stress mark is dropped alone. Structural validity does not certify phonetic correctness.
- `errors.ts`: `MissingApiKeyError` (App turns it into a key request: AI services on the purpose that needs the key) and `errorMessage(err, secret?)`, which also replaces a known key with `[redacted]` before a message is shown.

## Key flows

- **Article persistence:** startup awaits `initializeData(SAMPLE_ARTICLES)` then `loadData` before publishing readiness. The seeding transaction reads `meta.started` and writes samples plus the marker only when it is absent; deleting the last article keeps that marker, so reload stays empty. An editor save awaits `saveArticle` (one row plus `started`) before changing React state or navigating. While saving, the editor blocks further submissions, edits and dismissal; a failure keeps the draft and shows the real error for retry. Sample restore awaits `restoreMissingArticles`, which checks each candidate inside its transaction and returns the stored versions, never overwriting an existing edited sample. There is no article autosave, including during backup's delayed reload, so a stale library cannot delete, resurrect or overwrite unrelated rows. Backup import remains the deliberate atomic whole-store replacement. Concurrent explicit writes to the same row remain last-write-wins; cross-tab live synchronization and vocabulary/stats races are not handled here.

- **Look up a word or sentence:** reader or exercise/notebook source token → `App` sets the active word/sentence → `api.fetchWordAnalysis` / `fetchSentenceAnalysis` → cache hit or `tasks` → provider → cache → sheet renders.
- **Pronunciation markers:** article entry → cache-only validation and readiness recovery (no provider request); complete usable answers restore the saved per-article display choice and layer flags. Missing/expired/invalid answers retain plain reading and the direct toolbar switch opens generation settings. Only explicit Generate → `usePronunciationMarkers` → frozen `api.createPronunciationSession` (language/settings/template) → validate cache first → sequential `annotatePronunciation` tasks across the whole article → stage successes. A sentence whose answer fails validation gets one fresh request, then is skipped (stays plain, recorded per article) and the queue continues; provider/key/network errors still pause it. Marker view unlocks once every supported sentence is staged or skipped; Generate retries skipped sentences; the direct toolbar switch applies the prepared snapshot; Stop/input changes/unmount invalidate scheduling and state writes, but an already sent request may finish and cache its original result. Identity includes exact article content, ID, language, prompt fingerprint and schema/tokenizer versions; prompt/language changes reset the session. Sentences over 2,000 characters are reported, never truncated. Missing `Intl.Segmenter` retains plain reading. Rendering uses original source text and local grapheme references, not model echoes, and never adds audio synchronization.
- **Listen to an article:** the reader's Listen button → `startSequence` with the article's sentences (`splitArticle`) → each sentence plays through `speakFrench`, whose `onSettled` starts the next; the current clip is loaded first, then the next two are prefetched. Pausing or stopping synthesizes nothing more. `ArticlePlayer` (a fixed overlay) shows play/pause, previous/next and stop; Escape, another speak button or leaving the article ends it.
- **Hear text:** `SpeakButton` → `toggleSpeech` → `clips.loadSpeech` (stored clip, else `getAiAccess().synthesize`, then store) → `playback` publishes loading/playing through `state.ts`; every button with the same text reflects it.
- **Review vocabulary:** `VocabularyView` snapshots due words when a review starts; its fixed queue and index own the session total/progress while App persists ratings. Starting again rebuilds the queue from currently due words. Both interval previews and persisted ratings call `calculateNextReview`; the click recalculates against the actual review time. Deletion uses the existing callback only after a named Dialog confirmation; cancel preserves the word and history.
- **Save a word:** `App` stores the word with its analysis, then prefetches word and sentence audio so it is protected and offline.
- **Shadowing:** `ShadowingRecorder` → `useShadowingRecorder` (record, stop, play back) → `api.assessPronunciation` → `onAssessed` adds the score to stats.
- **Shadow a sentence:** the sentence pill's microphone → `usePracticeCard.open` claims the capture lock, pauses an article sequence (`suspendSequence`) or stops speech, then records a `Take` with a level meter → Stop → `addTake` (one transaction: the article still exists; for passages the unit, its passage and the captured content still exist; append, drop the oldest past 3) → the card shows the latest take. Any other playback (`setBeforePlay`) or the reader's word/sentence sheet interrupts a take without saving. Closing the card, switching source or its text, or leaving the reader discards a running take. A stopped take may finish saving, but its transactional ownership/content guard still applies.
- **Shadowing log:** My study → Shadowing → `useShadowingLog` (lists and subscribes to the store) → rows by source in `splitArticle` order; "open in reader" builds that source’s route with its sentence query.
- **Backup:** `DataSection` → `exportData` / `importData` in `db.ts` (never API keys; includes prompt edits; audio and shadowing recordings optional). Recordings are validated in full by `parseShadowingBackup` before one transaction replaces the stores; no `shadowing` key keeps the current recordings, `[]` clears them, malformed input rejects the whole restore. `units`, `itemStates` and `attempts` are always exported (no toggle). `importData` validates them with the Zod schemas in `exerciseBackup.ts` before the transaction opens (bad shape, duplicate ids, a state pointing at an unknown unit or item all reject the whole restore); a key that is absent keeps the stored rows, `[]` clears them. States of a replaced unit list that no longer match a unit or item are removed in the same transaction; replacing articles never touches units; attempts are only replaced when the key is present. A restore bumps the reset token of every unit that existed before it.
- **Check an answer:** the exercise screen grades (deterministically, or an AI grade for open answers) and calls `exercises.checkItem({ unitId, itemId, resetToken, answer, result })`, where `resetToken` comes from the sheet's `getUnitSnapshot(unitId)` read, before the work behind the result started. One transaction over `units`, `itemStates`, `attempts` and `meta` checks the unit and item exist and the token still matches, then writes the item state and one attempt (grammar tag, prompt, reference answer and answer text come from the stored unit). Any failure aborts the whole transaction and rejects (`StaleResetError`, `UnitGoneError`, `ItemGoneError`, or the storage error); the screen shows it and offers retry, never a fake success. An item that is already checked returns `{ created: false, state }` with the committed state and writes nothing, so a double click or a second tab cannot duplicate an attempt. Drafts and hint/explanation flags go through `saveItemProgress` (state only, no attempt; a checked item keeps its answer). Listeners of `subscribeExercises` run after commit and re-read.
- **Reset a unit:** `exercises.resetUnit(unitId)` deletes the unit's item states, increments its reset token and returns the new one, in one transaction; attempts stay. Work that started before (an AI grade, a hint, a delayed draft) still holds the old token, so its write rejects with `StaleResetError` and the screen drops it silently. The screen keeps using the returned token from then on. Deleting a unit, deleting its material (`deleteArticleData`: article, recordings, units and item states in one transaction) and restoring a backup bump the token too.
- **Generate exercises:** Practice → Add exercises dialog → `GenerateForm` (article, level, count) → `useExerciseGeneration.make` → `api.generateExercises(…, fresh)` → `tasks.generateExercises` (schema, then `keepAnswerable`) → `{ units, dropped }` → `toStoredUnits` (fresh ids, `unitNumber` from 1, a new `setId`, `setTitle` = the article's title, the form's level, `answerSource: 'ai'`, no `articleQuote`) → `exercises.saveUnits(units)` (one transaction; the batch keeps no link to the article, so the article can be edited or deleted meanwhile) → `subscribeExercises` refreshes the list. The button shows the work by swapping its icon and the fixed status line shows work or the real error; successful commit closes the dialog and the table shows the new set (a model answer the schema rejects is wrapped in a translated sentence, `utils/aiErrorText`). `MissingApiKeyError` goes to the key request (AI services → Text AI). Leaving the page does not cancel the request (the answer was paid for); it is still saved, and touches no screen state.
- **Conjugation drills:** Practice → Add exercises dialog → Conjugation drills → `ConjugationDrillForm` (pack verbs through `useGrammarPack`, tenses, level, items per exercise) → `verifyPackVerb` per checked row → `fromConjugation.prepareConjugationDrills` (one `WORD_TRANSFORM` unit per selected tense, items only from `reviewed`/`match` cells, `meta.strictAccents: true`) → `exercises.saveUnits` → the dialog closes and the sets table shows the batch; no AI request happens, so no key is needed. `useUnitSaver` (also used by the Conjugation page's "Practise this verb", which saves the same kind of batch for one displayed verb and then links to its `practiceSet` page) holds that payload and the one-save-at-a-time guard: a failed save keeps the prepared units; the next press retries the same payload (same ids), and any control change drops it. Grading goes through `effectiveStrictAccents`, so an accent-less answer is wrong whatever the Practice preference says, and the stored `CheckedResult.strictAccents` equals the flag used to grade.
- **Answer and check:** `UnitView` → `useExerciseUnit(unitId)` reads the unit, its item states and reset token together (`getUnitSnapshot`, one read transaction, so a reset or restore cannot split them), and keeps one `ItemRuntime` per item (answer, checked result, flags, what it is waiting for, the last error). Typing calls `setAnswer`: local state at once, and a draft write (`saveItemProgress`, state only, no attempt) after 350 ms of quiet, flushed on `pagehide` and when the unit is left. A failed draft write shows on the footer's status line; a stale token instead invalidates the session and reloads the stored sheet. A draft finishing after our own reset is ignored. Check waits until any pending hint on that item finishes (including Enter and Check all). Check (`exerciseUnit/actions.runCheck`) grades with `gradeUnitItem`; a `needs-ai` answer goes to `api.gradeOpenAnswer` (words only, never a score) and its feedback is stored in `CheckedResult.aiFeedback`. Both grading paths save the check-time `strictAccents` preference in `CheckedResult`, including when settings change while an AI grade is pending; then `exercises.checkItem` writes state and attempt in one transaction. Controls use this saved preference, never today's settings, for individual slot markings. Backups validate and preserve the boolean. Every write carries the token read when the work began. A result that arrives after the learner left the unit or reset it is dropped silently (`isCurrent`); a `StaleResetError` while the token is still ours means another tab moved it, and the unit is read again. Hint and Explain call `api.fetchHint` / `fetchExplanation`, show the answer (under the item, or in a `Sheet`), then save `hintShown` / `explanationShown`; only the flags are stored, so after a reload asking again is answered from the 30-day cache. Reset (`resetUnit`, after a confirmation that says the history is kept) returns the new token, clears the sheet and drops pending drafts. In-flight button locks belong to the session and reset token, so the new sheet can be checked immediately even while an old AI call finishes; a reset response after leaving or reloading the sheet cannot change its state. Enter and the character bar work through the text fields a control registers (`registerInput`), so a control never handles keys: `ItemRow` moves to the next blank, then the first empty one, then checks, and ignores Enter during IME composition; `CharacterBar` inserts at the cursor of the field the sheet bound on focus and never takes focus itself.

### Mistake notebook

`listMistakes()` supplies the latest wrong snapshot per unit/item and its resolved boolean; the notebook neither deletes history nor calculates substitute progress. A retry is a link to the surviving `#/practice/:unitId` sheet, preserving all current answers; its existing confirmed Reset is the only way to clear checked answers. Attempts carry no article or set; an entry has no link to one. Attempts of a deleted unit remain readable with no retry link. Explanations pass the exact prompt/userAnswer/expectedAnswer/grammarTag snapshots to `api.fetchExplanation`; source context is read only from the matching surviving unit. Mounted sheet ownership drops late replies after close, source change or unmount. Word token lookups pass explicit unit context into App; retries preserve that call context, and late/closed word requests cannot overwrite a newer lookup. No new store, persistence API or schema is involved.

### Exercise cross-links

`UnitView` passes App’s word callback into `UnitSheet`, which binds the loaded unit’s instruction and reading passage as explicit context (including an explicit empty string rather than a last-read fallback). Controls receive a local `onWord` callback only for non-answer prompt text; inline blank/choice segments retain the full original prompt as sentence context. Choice/tile buttons are never tokenized, and dictation audioText remains hidden. `InlineMarkup` renders only bold/code and escapes everything else through React; its token children preserve source punctuation and apostrophes through `readerTokens`/`ReaderWord`. Notes and explanation text share that renderer. No new persistence or AI pipeline is involved.

`ReaderWord` consumes Enter/Space before they reach `ItemRow`; registered answer fields retain their Enter/IME and character-bar behavior. App’s existing request counter, address ownership and retained retry context also guard exercise lookups. Explanation and word sheets may stack: only the last dialog handles a Sheet’s Escape, each Sheet focuses itself on mount and returns focus to a still-connected opener on close. There is no competing focus trap.

### Distinct passage sources and recording compatibility

`types/readerSource.ts` defines only `{ kind: 'article', articleId }` and `{ kind: 'passage', unitId }`, plus the read-only `ReaderDocument` fields the existing Reader draws. App resolves a passage only when the unit and its nonblank stored passage exist; the document takes its level from the unit and its source from the set label (`setLabel`). The title comes from the passage or unit, not fabricated article prose. No article snapshot, Library copy, new store or database upgrade is created on reading/navigation. Reader sequences, card targets and lookup ownership use the actual source; sentence and word replies are invalidated on close, source/address or exact Reader-content change. Passage Reader offers Back to exercises, not Make exercises. Marker sessions use the exact displayed content; article preference keys are the plain article id and passages use their explicit encoded source identity. Speech clips and validated annotation cache remain text-shared as before.

Article shadowing rows and backups use `articleId` and `${articleId}|${normalizedSentence}`. Passage rows have `passage: { unitId }` and no `articleId` (exactly one of the two); an `unitId` index on `passage.unitId` serves the set delete. Their disjoint key is `passage:` plus URI-encoded JSON `[unitId, normalizedSentence]` (no literal pipe), so identical sentences in prose and separate units never merge, even with delimiter/encoded IDs. `addTake` accepts the article-id string or an explicit source. Its articles/units/shadowing transaction checks that the article exists, or that the unit has the sentence and the captured passage content, before appending; any write failure preserves its real error and the card’s retryable take. Three-take FIFO and normalized sentence matching do not change.

Unit reset keeps takes and attempts. Unit deletion keeps passage takes as unavailable history; passage edits leave unchanged normalized sentences attached and changed sentences playable/deletable without a Reader link. Article deletion removes the article's prose takes through the `articleId` index in the same transaction and leaves passage takes alone; set deletion removes its units' passage takes through the `unitId` index in the same transaction as the units; attempt retention is unchanged. Optional recording backup carries exactly one owner per row. Parsing validates it and reconstructs source-isolated keys before writing. Restore does not tie a passage take to a unit: a take whose unit is absent is valid unavailable history and roundtrips its own backup. Without recordings, restore keeps existing rows (including now-unavailable history); `[]` clears them. Resolution never turns an absent unit into an article link. Cross-tab live synchronization remains outside this contract.
