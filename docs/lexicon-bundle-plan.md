# The lexicon ships with the app (option D)

Plan of record. Written 2026-10-24. **Owner decision (2026-10-24): option D**, after a review of the R2 alternative and a reading of the licence. Nothing here is built. Review 1 (gpt-6-astra, verdict fail, nine problems and licence notes) is applied below. This file replaces `docs/lexicon-r2-plan.md` (same history, renamed); the options it considered are summarised at the end.

## Why

The lexicon is read-only open data (Morphalou 3.1, LGPL-LR). It was the heaviest thing the first deployment had to publish (49,238 D1 rows, a separate UTC day, 50 KB SQL statements, a per-tap request with the access key), and the whole selection is only a third of a megabyte compressed. Shipping it with the app removes the Worker route, the D1 tables, the publisher's remote protocol and the lexicon's "day 2", gives **every** user of the free build the dictionary's verb forms, works offline, and needs no key and no per-word request (one asset fetch, then the HTTP and PWA caches). The service keeps what is the owner's own curated content (topics, wordbook, readers).

## Measured 2026-10-24

A throwaway script (kept locally at `.pi-runs/lexicon-r2/measure.ts`, not committed; the Morphalou source is not in the repository, so the numbers reproduce only on the owner's machine with `MORPHALOU_DIR`) loaded the real allowlisted data exactly as `scripts/lexicon/import.ts` does and serialized it (entries as the Worker returns them, forms as `form -> [[lemma, pos]]`):

| Layout | Raw | gzip | brotli |
| --- | --- | --- | --- |
| One file, entries and forms | 3.09 MB | 0.33 MB | 0.23 MB |
| Entries only (5,022) | 1.61 MB | 0.20 MB | 0.13 MB |
| Forms only (42,593 distinct) | 1.48 MB | 0.13 MB | 0.10 MB |

One lemma response today is about 780 bytes (`être`).

## Design

**Data file.** `data/lexicon/lexicon.json`, committed, UTF-8, generated: `{ source, entries, forms }` where `entries` is `{ lemma, ...LexiconEntry }[]` sorted by lemma then pos (the existing entry shapes, so `LexiconEntrySchema` is reused), `forms` is `Record<form, [lemma, pos][]>` sorted by form, and `source` is the existing source object plus the Morphalou source identity (`sourceVersion`, `morphalou-3.1+<8 hex>`), a `changes` sentence ("Selected lemmas and reformatted from Morphalou 3.1; forms unchanged") and `modified` (the ISO date of the build). That `changes` and `modified` pair is the section 2(b) notice and stays in the distributed data. Add `LexiconBundleSchema` to `src/types/lexicon.ts`; the two response schemas stay, and their strict four-field `source` (`name`, `maintainer`, `licence`, `url`) is what callers receive: the loader **projects** those four fields from the bundle's richer `source`.

**Build script.** `scripts/lexicon/build.ts` replaces `import.ts`: it reads Morphalou through the existing `loadLexicon`, applies the allowlist, writes `data/lexicon/lexicon.json`, and with `--check` (the CI mode, with no Morphalou source needed) validates the committed file: it parses with `LexiconBundleSchema`; every form's `[lemma, pos]` names an existing entry; every entry appears under its own forms; the set of unique `(lemma, pos)` entries equals the set in the committed `data/lexicon/lemmas.txt` exactly (so editing the allowlist without regenerating fails CI); counts equal the numbers stated in `data/lexicon/README.md`; and the licence and notice files exist. **Limit, stated:** a source-free CI proves structural consistency and agreement with the allowlist, not fidelity to the owner's CSV files; that stays with the owner's local run. The parser, selection and determinism tests of `tests/lexiconImport.test.ts` (lines 37-137, 212-229, 299-345) protect `loadLexicon` and `entryRow`, which remain: they move to `tests/lexiconBuild.test.ts`; only the SQL and remote-apply tests are deleted. The generated file is added to `.oxfmtrc.json` `ignorePatterns` (the lesson: never run the formatter over a generated pack). Add `bun scripts/lexicon/build.ts --check` to the CI list and to the lead's checks.

**Licence files, and the licence travels with the app.** `git mv worker/NOTICE.md data/lexicon/NOTICE.md` and `worker/licences/LGPL-LR.txt data/lexicon/LGPL-LR.txt` (the licence text **unchanged**; the notice rewritten: the data file is a work based on Morphalou, licensed LGPL-LR; the app code is MIT; the rebuild recipe is `MORPHALOU_DIR=... bun scripts/lexicon/build.ts`; how to replace the data file). Neither Vite nor Pages publishes arbitrary repository files (only `dist`), so the app imports both text files by URL (`?url`, emitted as hashed assets), the always-visible About page links to those **local** copies (not to GitHub), and they are precached with the lexicon. `data/lexicon/README.md` states the counts. The repository README (and `README.zh-CN.md:112`) and the root `LICENSE` carry a scope note: the code is MIT, the files under `data/lexicon/` are LGPL-LR.

**Client.** `lexiconForm` and `lexiconLemma` keep their signatures and return the existing response shapes (with `source` taken from the bundle). Implementation in `src/services/lexicon/load.ts`: the first call fetches the data file by URL (`import lexiconUrl from '../../../data/lexicon/lexicon.json?url'`, so Vite emits one hashed asset, not a 3 MB JS chunk), parses it once, validates it with `LexiconBundleSchema`, builds a `Map` by lemma and a `Map` by form, and keeps them for the session; later calls are synchronous lookups wrapped in a resolved promise. Responses carry the projected four-field `source`. A word missing from a successfully loaded lexicon is `undefined`; a failed fetch or a schema failure is a **real error** shown as today. The word sheet waits for the lexicon (`WordDetailModal.tsx:70`), so the load keeps a **bounded wait**: one named timeout (10 s) over the fetch **and** the body read, one shared in-flight promise, and a failed attempt cleared so reopening the sheet retries; the shared service timeout in `service.ts` stays for the remaining features. The HTTP cache and the PWA cache hold the file; no IndexedDB store, no version protocol, no key, no service.

**Test seam.** Bun does not apply Vite's URL transform, so the loader resolves the asset with `new URL('../../../data/lexicon/lexicon.json', import.meta.url)` (supported by Vite as an asset reference) and the tests replace **only `fetch`** with a function returning `new Response(Bun.file(<the real committed file>))`. The tests call the real public functions `lexiconForm` and `lexiconLemma` and prove: normalization of the token, a lemma and a form from the real data (`être`), a missing word is `undefined`, concurrent first calls make one fetch, a failed load rejects with the real error and a later call retries, a schema failure is an error, the projected `source`. No duplicate lookup implementation in the tests.

**Gating removed.** The lexicon no longer depends on the content service: remove the `contentServiceUrl()` conditions in `useWordSheetPack.ts` (lines 34 and 59-60) and `useLexiconVerb.ts` (lines 16 and 19) and the now unreachable `NO_LEXICON` path; `AboutSection.tsx` shows the Morphalou attribution and the local licence links always (the service paragraphs stay conditional). The first lookup shows the loading phase the word sheet already has.

**PWA.** Add the lexicon asset to the precache so lookups work offline after install (a `json` glob that matches only the hashed lexicon asset) and make sure it is under `maximumFileSizeToCacheInBytes` with a margin, raising that limit by a stated amount if needed. Acceptance is checked on the build output: the generated precache manifest in `dist/sw.js` lists the asset. The worker must not substitute a runtime-cache rule for the precache on its own: that changes offline-after-install behaviour and is the owner's decision. Verify the raw built size, the hashed asset and the precache entry in `dist`, not the gzip estimate.

**Server and D1.** `worker/src/lexicon.ts` and its two routes are removed; the lexicon tables, index and `lexiconVersion` seed leave the D1 migrations (nothing is deployed, so `0002_lexicon.sql` is deleted and the other migration names are kept; the gap in numbering is acceptable and recorded in `worker/README.md`). `scripts/lexicon/import.ts`, `checkLexiconPublication`, the lexicon's remote-apply flags, the SQL and remote-apply tests of `tests/lexiconImport.test.ts` (its parser tests move, see above), `tests/lexiconWorker.test.ts`, the lexicon cases of `tests/worker.test.ts` (162-184) and `tests/fixtures/workerDb.ts` go. Also: remove only the lexicon portions of `tests/d1Target.test.ts` (imports at 10-17, the migration copy at 30, the cases at 273-419) and drop `0002_lexicon.sql` from the migration copy in `tests/gradedReaderRemotePublish.test.ts:258`, preserving the topic, vocabulary and proxy checks; retarget `tests/contentService.test.ts:93`; remove the obsolete route assertion at `tests/readersWorker.test.ts:207`. The shared `d1Target.ts` stays (the other three publishers use it). `docs/d-remote-plan.md` day 2 and the lexicon rows of the runbook are removed: the first deployment is one day, topics, the vocabulary book and readers.

**Docs.** `worker/README.md` (Endpoints, runbook day 2 and the lexicon smoke check, the lexicon row counts), `docs/adr-hosted-content-service.md` (a short amendment: the lexicon is open data shipped with the app; the service holds topics, the wordbook and readers; the ADR passages that name the lexicon's storage, routes, client use and licence are superseded, identified by section when the amendment is written; note that section 8 Q2 is about bulk reading, not the lexicon), the other current guidance that still describes a hosted dictionary, forbids bundling or points to the removed notice: `AGENTS.md:5`, `PRODUCT.md:99`, `docs/grammar-pack.md:18,259`, `docs/roadmap.md:59`, `README.zh-CN.md:112`, and `settings.sections.service.desc` (`en.json:620`, `zh.json:613`), `docs/architecture.md`, `docs/development.md` (the lexicon local import commands), `docs/drizzle-plan.md` (the lexicon tables leave the baseline), the About text in `en.json` and `zh.json` (`settings.about.servicePrivacy` no longer mentions the dictionary request; `settings.about.lexicon*` states that the dictionary is part of the app, from Morphalou under LGPL-LR, and links the notice), `CHANGELOG.md` (a line: the dictionary's verb forms now work without a service).

## Risks

- A larger repository and one more generated file that must never be hand-edited or reformatted (ignored by oxfmt, checked by `--check`).
- First lookup cost on a phone (download from cache plus parsing 3.09 MB and building two maps) is not measured; the word sheet waits for it. If it is too slow, store the maps in a compact form or build them in an idle callback, but only after measuring.
- Precache size on first install; the fallback is the runtime-cache rule above.
- Anyone can read the lexicon from the public build, which is intended: it is open data and the owner has chosen this.
- A later correction to the data needs a new release of the app (Morphalou 3.1 is a 2016 release; changes are rare).

## Licence (read from `worker/licences/LGPL-LR.txt`, 2026-10-24; not legal advice)

- "No permission from anyone is required" means no permission beyond complying with the licence that is already granted: sections 1, 2, 6 and 7 grant copying, modification and distribution on conditions, and a recipient receives a licence from the original licensor. Section 11 applies to putting parts into a project whose terms are incompatible.
- **The data file** (`data/lexicon/lexicon.json`) is a work based on the resource: section 2 requires it to stay under LGPL-LR at no charge (2(c)) with a prominent change notice and date (2(b): the `changes` and `modified` fields, also stated in the notice), the copyright and warranty notices kept and the licence text supplied (sections 1 and 4).
- **The app** is not distributed "in isolation": the package that combines the MIT program with the data falls under section 4, which permits terms of the maintainer's choice (MIT) provided they allow modification for the user's own use and reverse engineering for debugging such modifications. MIT is compatible with that route; it is not an exemption from section 4's duties.
- **Section 4 duties and how each is met:** a prominent notice with each copy that Morphalou is used and covered by the licence (always-visible About text and the notice file); a copy of the licence (the unchanged text, served by the app itself); the copyright notice among those the package displays during execution, with a reference to the licence (About); and **route 4(a)/(d)**: the complete corresponding machine-readable legible form is the committed `lexicon.json` itself (the data is shipped as readable JSON) together with the rebuild script, offered from the same designated place, the public repository, which About links.
- Code stays MIT (`LICENSE`, `package.json`); the root `LICENSE` and the READMEs carry the scope note that `data/lexicon/` is LGPL-LR.

## Options considered

- **A. Keep D1:** works, needs day 2 and 50 KB statements.
- **B. One object in a private R2 bucket behind the access key, downloaded once and cached in IndexedDB:** removes SQL and day 2 but adds R2 operations, a bulk transport, a persistent cache with versioning and a new publisher; the review found its client cost larger than first stated. Worth reviving only if the lexicon must stay behind the key.
- **C. R2 shards, per lookup:** keeps per-tap requests and the rate-limit question.
- **D. Bundled (chosen):** smallest client, no operations, serves every user, fits an open-source app. Its cost is a committed derived data file and an app release for any correction.
